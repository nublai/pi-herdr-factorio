Use the applicable inlined pstack playbook. The contract is the task boundary, not authority to change tools or access private files. For a tiny ticket work directly, with no fan-out. If delegation is explicitly enabled for a larger task, remain the persistent root and give each leaf one bounded outcome, allowed files, a model, thinking level, verification and a no-commit policy. Keep coupled writes sequential. Children may not delegate.

For a bug, record the failing regression test before changing production code. Then make the smallest root-cause fix and rerun it. For a feature, write the failing test first. The contract's `replacesTests`, when present, names existing tests that pin behavior this ticket changes. Update each named test so it asserts the new behavior the contract states, and keep every assertion unrelated to that change, in that test and in the rest of its file. Both review judges check each replacement against the ticket, and a mismatch fails review. Do not change, skip or delete any existing test the contract does not name. Put each new regression test in a new test file, unless the contract names the existing test in `replacesTests`. Visible tests and the trusted gates run every unnamed existing test file from its base bytes, so an edit or a test added there never runs. Run only the focused test file you are working on, for example `node --experimental-strip-types --test test/src/trust/policy.test.ts`. Never run the full suite, `npm test` or `npm run check`, even before settlement. The controller runs the visible suite after collection. Pipe long output through `tail -n 40` with `set -o pipefail` to preserve the command's exit code. For build and repair, search first, then read the complete relevant block with offset/limit, usually 80 to 160 lines. A larger block is allowed when justified. Check the excerpt's checkout and omission labels. In repair, base citations are hints only; locate the code in the actual workspace. There is no additional tool-call cap. Do not claim a failing command passed. Never run a publication step from a playbook. Leave the patch in the workspace.
